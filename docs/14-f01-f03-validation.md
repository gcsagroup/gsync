## 2. F01：锁定取消敏感操作

锁定先撤销当前界面会话，再等待存储清除解密钥匙；旧编辑、待展示的导出结果和异步解锁／回读不能恢复已失效会话。主界面与子窗口在锁定事件中清空编辑条目、字段副本、导出数据和显示密码状态，并关闭相应窗口。

编辑提交同时核对空间与界面会话，防止旧窗口在重新解锁之后继续提交。待确认请求记录所属空间，锁定该空间时拒绝一次，过期窗口的回调不能再批准；锁定无关空间不会取消另一个仍解锁的保险库请求。

已处理实际操作中发现的首次编辑空白回归：编辑弹窗直接绑定所选条目，并只在锁定事件清理内容。复测时已有标题、网址、用户名及秘密字段正确带入。

| 场景 | 结果 |
| --- | --- |
| 已有条目编辑中显示合成密码，再执行 Command＋Shift＋L | 通过：编辑窗口关闭，界面仅显示解锁入口，原密码显示按钮不可继续操作 |
| 修改标题但不保存，然后锁定并重新解锁 | 通过：仍为原始条目；两份合成库与修复前备份逐字节一致 |
| 锁定后旧编辑向重新解锁的库提交 | 自动化通过：被拒绝；使用新会话的合法提交仍可完成 |
| 当前保险库与另一收藏夹独立锁定 | 自动化通过：锁定收藏夹不关闭当前保险库会话／合法审批；锁定审批所属库会取消请求 |
| 待确认请求取消后旧窗口再次批准 | 自动化通过：只收到一次拒绝，旧回调不生效 |
| 五分钟空闲锁定 | 通过：自动化时间边界通过；实际等待原有五分钟时限及检查周期后，未提交的系统 CSV 导出窗口自动关闭，回到锁定界面，无文件导出 |
| 物理 Mac 系统锁屏、iPhone 真机进入后台 | 本轮未执行；相应事件仍调用同一锁定路径，不能以单元测试代替系统实际验收 |

普通 Swift 状态清除和视图销毁不等于已证明内存安全擦除。已完成的文件导出也不在“取消未完成导出”的含义中。剪贴板所有权等 F12 其他事项没有顺带修改。

## 3. F02：KDBX 只生成候选，拒绝原地替换

移除来源文件的替换分支。`kdbx-write --apply` 在读取、生成候选或操作来源之前直接拒绝，退出码为 2，并说明外部客户端可能并发保存。默认命令生成独立候选，重新加载核对修改、未知字段、附件与历史，返回 `canApply=false`、来源基线和生成期间来源是否变化的状态。

这解决了已复现的“最后检查与替换之间覆盖新修改”路径，代价是当前没有原地自动写回。必须在来源客户端核对、合并候选；不能把这一安全限制称为外部库持续双向同步完成。

验证使用真实 pykeepass 库及合成 KDBX，并直接执行连接器 CLI：

- 默认命令退出码 0，候选能独立打开，密码更新正确，未知字段、附件和历史保留。
- 源文件始终保持原字节；`--apply` 退出码 2，不创建备份或替换源文件。
- 在读入源库后插入另一客户端保存，来源的新版本完整保留，结果标注 `sourceChanged=true`；继续请求 `--apply` 仍被拒绝。
- 未支持的候选字段仍被拒绝；已有的来源选择和异常 ZIP 防护测试继续通过。

没有声称已经完成 KeePassXC／KeePassDX 的真实双客户端写回验收。自动替换入口已经关闭，这类产品能力仍归后续 F08 处理。

## 4. F03：内嵌版本与构建记录一致

XcodeGen 及四个 Info.plist 使用同一组构建变量。构建脚本对最终主 App 与凭据扩展读取版本、构建号、Bundle ID 和数量，任何不一致立即失败；Mac 包额外执行 `codesign --verify --deep --strict`，成功回执保存在 `build/product-平台-编号.json`。

| 平台 | 连续成功构建回读 | 最终回读 |
| --- | --- | --- |
| Mac 主包／凭据扩展 | 1.0 (8) → 1.0 (10) | 两者均为 1.0 (13) |
| iPhone 模拟器主包／凭据扩展 | 1.0 (9) → 1.0 (11) | 两者均为 1.0 (14) |

Mac 设置页实际显示 **Ver 1.0 (13)**，与产物回读一致。

编号在平台和测试编译之间共用，因此允许跨平台间隔，不代表遗漏构建。每次均复用现有固定路径。Mac 使用本机临时签名，模拟器产物没有正式分发签名；这些边界没有改变。

反向测试覆盖：凭据扩展仍为旧版本、扩展 Bundle ID 错误、扩展缺失，均不能取得成功回执。正常 Mac／iOS 产物结构与四个生成声明通过。
