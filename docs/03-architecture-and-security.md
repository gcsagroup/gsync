# 架构与安全设计

文档版本：0.1  
更新日期：2026-11-06（北京时间）  
状态：建议设计；密码学实现、依赖、协议和选型须在 M0 定稿并验证

## 1. 设计目标与边界

对应 R02、R04、R10—R17、R19—R21。核心目标是自有数据可以离线使用、跨设备同步和独立恢复；外部来源作为连接器接入，不影响基本数据访问。

使用成熟密码学库与系统安全能力，不自行创造加密算法。本文定义必须实现的属性和模块边界，不是已经完成安全证明的密码学协议。

## 2. 最少必要模块

| 模块 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| App 界面 | 收藏夹、保险库、连接状态、恢复引导、导入报告 | 不直接拼接或执行来源库命令 |
| 本地数据与密钥模块 | 加密存储、解锁、历史、恢复材料、完整性验证 | 不把主密码上传给同步服务 |
| 同步模块 | 版本、离线队列、合并、重试、设备确认、存储迁移 | 不替外部来源绕过授权 |
| 存储适配器 | WebDAV、本地文件夹、后续官方云的密文读写 | 不解释明文条目或代为解密 |
| 来源连接器 | 读取／写回获授权的数据、字段映射、来源状态 | 不把所有连接默认串联传播 |
| 浏览器扩展／系统提供器 | 用户触发的收藏夹和凭据操作、页面／App 身份校验 | 不取得整个保险库的无限制明文访问 |
| 本地云验证服务 | 账号与密文对象、版本条件、设备接入、备份恢复验证 | 不在本轮公开上线，不持有解密私钥 |

优先同一核心逻辑复用，避免每个平台各写一套冲突算法。正式 API、文件布局和序列化版本须在跨端原型后冻结。

## 3. 技术选型建议

| 部分 | 建议候选 | 定稿前验证 |
| --- | --- | --- |
| macOS／iOS 界面及系统集成 | 原生 Swift／SwiftUI | 凭据提供器、目录授权、签名、扩展、最低系统版本 |
| 跨端同步与数据核心 | 评估 Rust 共享库，或可复用的原生核心边界 | KDBX 库、加密库、FFI、移动端构建、内存和许可证；不能仅因偏好增加一套语言 |
| 浏览器扩展 | TypeScript 与各浏览器 WebExtensions 适配 | Chromium／Firefox 生命周期、权限、消息通道、安装分发 |
| Android 与 Windows 界面 | 在 Apple 原型稳定后定平台实现 | 系统提供器、解锁、安全存储、共享核心集成 |
| 持久化 | 本地事务索引＋版本化加密内容的候选方案 | 索引是否泄露、崩溃恢复、文件数量、手机目录提供器性能 |
| 自有保险库格式 | 版本化、可公开解析的加密格式；是否直接采用 KDBX 待评估 | 完整类型、恢复机制、增量同步、Passkey、自定义字段和互操作 |

不能为了 KDBX 兼容就宣称自有库必须等同 KDBX，也不能未经评估自创一个无法完整导出的专用格式。M0 应做“成熟格式＋旁路同步元数据”和“独立加密格式＋KDBX 适配器”对比，按验证成本和数据保真作决定。

不因本文选型候选安装依赖、创建多个容器或修改其他项目。

## 4. 数据空间与账号

收藏夹空间和每个保险库有独立 ID、独立密钥及主要存储绑定。独立入口不能只靠隐藏页面实现，应在密钥访问层隔离。

自备存储用户在本机创建空间，通过 WebDAV 凭据或目录授权连接存储，不依赖官方账号。官方云账号只用于服务访问、设备会话等，不等于主密码；找回账号不能解密既有保险库。

建议自备存储模式在官方服务完全不可达时仍可创建、连接、解锁、同步和恢复，作为离线依赖测试。云验证码、遥测、许可检查不得变成暗中必需依赖。

## 5. 密钥与恢复

### 5.1 必须满足的属性

- 每个数据空间随机生成数据密钥，使用经过审查的认证加密实现。
- 主密码通过成熟的口令派生方案保护密钥；盐、参数和格式版本可迁移，参数在真实设备上测量后确定。
- 恢复密钥是独立高熵秘密，可以恢复数据密钥；不能由邮箱、账号密码或设备名称推导。
- 密钥与密文分离管理；存储后端、日志和备份目录不保存可直接解密的恢复秘密。
- 每个密文对象需绑定数据空间、对象身份、协议版本及密钥代次；拒绝跨库替换、篡改和未知关键版本。
- 附件、历史、回收站、原始导入字段和同步变更都属于需加密内容。

认证加密模式、密钥派生参数、随机数与 nonce 策略、密钥封装格式由安全设计评审后落实；在跨端已知答案测试和篡改测试完成前，不使用真实密码进行内部试用。

### 5.2 新设备接入

支持两条独立路线：使用主密码／恢复材料从存储恢复；或由仍有解密能力的已授权设备批准。后者不能成为 iPhone 的唯一接入方式。

设备授权需要验证对端身份、一次性会话与过期时间，避免把“知道存储地址”当作获得解密权限。配对秘密不进入日志，不放在可重复使用的公开链接中。

### 5.3 恢复与变更

| 操作 | 设计要求 |
| --- | --- |
| 忘记主密码 | 有恢复密钥或仍可解密的授权设备时才可恢复；需要对应密文数据仍存在 |
| 修改主密码 | 通常更新密钥保护关系；不能宣传为已消除旧密文副本或旧密钥风险 |
| 恢复密钥重置 | 验证新材料可用后才撤销旧保护入口；处理仍保留旧密钥封装的备份 |
| 设备丢失 | 撤销未来访问，必要时轮换密钥与存储凭据；不能远程抹除已复制的明文 |
| 全部秘密和可用设备丢失 | 官方无法恢复旧库；重新注册账号不改变这一事实 |
| 备份恢复 | 校验库 ID、版本、密钥和完整性；预览后恢复为新版本，不能无提示覆盖当前库 |

已授权设备仅在仍有解密能力时有恢复价值。仅在设备列表里有一条记录，或者拥有一个已完全锁定且没有可用解锁材料的安装，不足以恢复。

## 6. 锁定、离线和后台

默认锁定条件、闲置超时、剪贴板清理时间列为待定配置，不凭讨论自动选一个固定分钟数。系统锁屏、应用失去可用授权及用户手动锁定均须测试。

锁定时可研究上传已经形成的密文和下载待处理密文；需要明文的索引、合并、外部写回或填充可等待解锁。产品要区分“密文已到达”和“已完成合并”。

iPhone 前台能够独立同步；后台只使用合法机制并遵守系统调度。无后台机会时在下次前台运行补齐，不能伪装成持续在线。[后台依据](08-references.md#s22)

## 7. 扩展与填充边界

- 网站脚本不能通过扩展通道读取任意条目；只允许经过身份核对的当前操作。
- 本地消息通道验证扩展标识、调用方和请求上下文，避免任意进程调用明文接口。
- 扩展与系统提供器只接收完成当前填充所需的字段，不长期缓存整个保险库。
- 主动触发为默认。自动填入按用户允许的网站启用；跳转后重新校验目标身份。
- App 身份按系统提供的可验证关联处理；标题相似、窗口文字或进程名不能独自证明身份。
- 跨域 iframe、HTTP、相似域名、隐藏字段和页面在填充前变更均需独立测试。
- Mac 辅助功能方案如进入研究，必须显式授权、限定目标窗口，且验证焦点变化时中止；不以后台键盘记录获取密码。
- 生物识别是本机解锁便利能力，不替代新设备恢复或主密钥设计。

## 8. 外部来源连接

每个连接有明确的来源身份、保险库范围、字段能力、方向和授权状态。用户开启一个连接，不代表授权所有其他来源之间复制。

源数据在客户端转换并加密；不经由官方服务器解析明文 1PUX、CSV 或 KDBX。对外部文件写回采用副本、完整性验证与条件提交；未知字段无法保真时拒绝破坏性写回。

1Password CLI 的会话授权不能被当作永久令牌；锁定或撤销后暂停连接并保留本地变更。[授权依据](08-references.md#s15)

实验性连接默认关闭，列出实际使用的权限与局限。App Store 目标不因“实验性”标签就放宽公开 API 和数据访问约束。外部来源能力不足不能靠关闭安全策略解决。

## 9. 存储信任与备份

把 WebDAV、网盘和官方云视为可能丢失、重复、乱序或返回旧数据的存储。认证加密解决内容篡改，不自动解决所有历史回滚问题。

保存已验证的版本检查点并比较设备进度；已见过的新版本不应悄悄退回旧版本。全新设备仅看到一个自洽旧快照时，可能无法独立判断它是否最新；需借助其他设备或独立备份，不能声称对任意恶意回滚完全免疫。

一个保险库只有一个主要同步位置。备份为明确版本的加密副本，不监听并自动合并回主库。迁移按“冻结写入窗口或排队 → 完整复制并校验 → 发布新位置与代次 → 设备重新连接 → 保留旧快照”执行；不得长期两个位置都作为主库。

移除设备时，还需考虑它仍持有 WebDAV 凭据或网盘权限。轮换密钥、设备授权和存储访问权限是不同动作，界面和文档不能只删除一个设备条目就宣称全部撤销成功。

## 10. 威胁与必须验证的控制

| 威胁 | 控制与测试 | 现实边界 |
| --- | --- | --- |
| 服务器／网盘泄露 | 内容和附件端到端加密，检查上传包、索引与日志 | 访问时间、对象大小等元数据可能仍可见 |
| 离线猜主密码 | 合适的口令派生成本和恢复材料设计 | 弱口令不能因加密而变强 |
| 恶意网页诱导填充 | 来源绑定、主动触发、跨域与隐藏字段测试 | 用户主动向错误站点提交仍需清楚反馈 |
| 导入文件攻击 | 限制解析大小、深度、路径、压缩比；不执行 HTML 或附件 | 导入源不可信，文件预览不代表安全执行 |
| 文件写入中断与并发 | 原子发布候选、幂等合并、历史和完整性检查 | 网盘与 NAS 行为必须实测，不能假设一致 |
| 日志／临时文件泄露 | 脱敏、最少保留、受保护临时目录、退出清理 | 外部工具产生的明文导出不能保证从 SSD 永久抹除 |
| 终端已被完全控制 | 最少解锁时间、系统安全存储和及时撤销 | 不承诺在已被控制且库已解锁的设备上保护全部明文 |

安全要求服务于具体密码与同步功能，首版不额外引入复杂企业审计、远程控制或威胁情报服务。

## 11. 发布与开发环境

iPhone 使用可公开发布的原生与扩展机制。Mac 是否同时提供官网签名包和 Mac App Store 版本，在 M0 根据扩展、辅助能力和分发限制确定，不推定两个渠道都能完全同等支持。

Mac 固定 App 路径建议采用项目下 `build/GCSA-PBsync.app`，具体路径在第一次构建前确定后复用。每次构建、测试打包递增构建号；文档版本与 App 版本分别管理。

本地云与 WebDAV 测试尽量复用一个开发容器、镜像和数据卷，场景顺序切换；如果直接用本机临时服务即可验证，就不额外引入容器。本次尚未创建任何运行环境。
