# 数据与同步规则

文档版本：0.1  
更新日期：2026-11-06（北京时间）  
状态：语义规则与协议候选；线格式和具体算法待 M0 验证定稿

## 1. 规则优先级

R05、R08、R09、R10、R16、R18 是已确认要求。本文补充幂等、删除、重复导入和并发处理细节，均为建议设计。对外文案不得暴露内部对象 ID 或协议术语，除非有助于用户处理具体故障。

## 2. 逻辑对象

| 对象 | 必要语义 | 保密要求 |
| --- | --- | --- |
| 数据空间 | 类型、稳定 ID、协议版本、密钥代次、主要存储绑定 | 除路由必要标识外加密；名称不作为远程明文路径 |
| 收藏节点 | 稳定 ID、父节点、节点类型、标题、URL、同级顺序、来源映射 | URL、标题和目录内容加密 |
| 保险库条目 | 类型、字段、多网址／App 关联、备注、标签、附件引用 | 内容与来源标识加密 |
| 历史版本 | 条目快照或变更、来源、发生时间、版本关系 | 与当前内容同等保护 |
| 删除记录 | 对象 ID、版本、删除操作、回收信息 | 参与认证和加密，不能只依赖文件不存在 |
| 附件 | 内容引用、大小、类型、完整性标识、版本 | 名称与内容加密；不以明文跨库哈希泄露相同附件 |
| 来源映射 | 来源实例／账号／库／条目身份与本地对象的关系 | 不能仅按网站或用户名识别身份 |
| 同步操作 | 唯一操作 ID、作者设备、因果父版本、发生时间、序号、有效载荷 | 身份、版本与内容绑定验证 |
| 设备检查点 | 已接收／已应用版本、存储代次 | 验证真实性；不把收到字节视为已完成应用 |

具体字段名、编码、公开头部、签名与密钥派生方案通过安全评审后定稿。本文不提供可直接投入真实数据的协议实现。

## 3. 核心不变量

1. 同一份有效操作集合，在任意接收顺序下得到相同结果。
2. 重复接收、重试上传和重复启动不会重复创建同一对象。
3. 本地修改先持久化，上传失败不丢失；成功回执必须对应可验证的持久状态。
4. 不因一方文件暂时缺失就推断条目删除。
5. 合并按对象或字段的已定义边界进行，不用“最新整库文件覆盖旧整库文件”代替同步。
6. 认证或解析失败时不覆盖本地最后一个有效版本，不把空结果当作空库。
7. 外部写回必须在声明字段范围内；不能因格式不支持而删除未知数据。
8. 一个数据空间在同一存储代次只有一个主要位置，备份不产生同步操作。

## 4. 修改冲突：自动采用较新版本

这是用户选择，取代“冲突必须手动选择后才能继续”的早期建议。

建议先按因果关系判断：一个版本明确基于另一个版本修改时，后继版本优先。并发版本采用带逻辑序号的时间记录和固定决胜顺序，所有设备使用同一规则；不得以下载时间、文件修改时间或最后到达的请求作为唯一依据。

M0 需要定稿并测试：时间来源、时钟异常阈值、同时间决胜、离线初次连接、外部来源缺少原始修改时间时的处理。并发顺序候选应有稳定设备／操作 ID 决胜，保证结果不随网络到达顺序变化。

物理时钟严重偏差时无法证明现实中谁最后修改。仍按确定性规则选取有效版本并保留双方历史，显示时间异常说明；不把“不知道真实先后”描述成精确知道。该处理不默认改回人工阻塞。

密码更新按完整凭据版本处理，不把两个冲突密码拼接。附件引用、类型和必要字段一并验证。恢复旧版本会生成新操作，再传播到已授权连接。

**外部限制：** 如果来源不提供可信版本或修改时间，首次合并使用预览；后续连接器必须保留上次同步基线。没有足够信息时不能宣传为已实现完全自动“最新优先”。

## 5. 收藏夹树

### 5.1 范围与初次连接

用户明确连接的浏览器配置文件参与全量同步。配置文件不是仅凭浏览器名称识别；工作与私人配置文件分别连接，避免无意混合。

建议统一逻辑根目录，再将书签栏、其他书签等映射到各浏览器根。只读／组织管理节点列为限制，不尝试修改。根映射与不支持节点在首次预览中说明。

初次合并先读取完整树、建立快照、计算差异和预览，再批量写入。不能用一个空的新空间自动清空现有浏览器。

### 5.2 重复与移动

- 不仅按 URL 去重：同一 URL 在不同文件夹、多账号站点或不同业务目录中可能是用户有意保留。
- 同一来源稳定 ID 对应同一对象；跨来源无 ID 时用完整路径、URL 和导入指纹辅助匹配，不确定项展示预览。
- 移动是对象父节点或顺序变化，不是删除后重建；保留身份以降低重复。
- 并发移动造成目录环、父节点删除或根越界时，保持数据可访问并放入明确的待整理位置，记录原始父关系；不得丢弃子树。
- 排序候选采用稳定顺序标识；并发插入和重复排序应收敛，算法在 M0 定稿。

### 5.3 事件回环

本产品写入浏览器触发的事件需识别并去重，但不能简单忽略一段时间内所有事件。若用户同时手动修改，必须捕获。扩展重启后能通过基线比对补齐事件。

浏览器自带同步可能把远端内容再次带回。用对象映射、版本基线与内容比较抑制重复，不擅自关闭用户的浏览器账号同步。

## 6. 删除、历史与回收

建议以显式删除操作参与版本排序，并保留可恢复历史。删除与修改并发时遵循已定稿的版本顺序：较新删除则进入回收站；较新修改可恢复为当前条目并记录事件。不得在不同设备采用相反规则。

批量删除或目录删除提供影响预览与恢复快照。真正清除历史是单独操作，不等于普通删除，不能自动传播成外部来源的不可逆永久删除。

删除记录保留期限与容量阈值待定。清理前考虑长期离线设备；不再被信任的过旧基线需要完整重新同步，防止已删条目复活。清理不会承诺抹除第三方备份中的旧秘密。

## 7. 外部来源映射与传播

每条连接明确：来源账号／库、目标库、方向、字段能力、授权状态和上次基线。只读连接不产生外部写回。

外部来源库属于互操作对象，不是自有保险库的第二个主要同步位置。例如自有库使用 WebDAV 时，连接一个 KDBX 来源不意味着把 KDBX 文件也当作自有库的另一个同步后端。

同一目标库连接多个外部来源时，首次设置必须显示可能传播的目标。不能因一个库被选中，就默认新增所有可能的连接边。每次写回带来源标记或本地去重基线，防止 A→本产品→B→本产品→A 无限重复。

外部源已锁定／不可达时，用户在本产品的修改可以继续保存；显示待写回数量。重连后先读取来源当前版本再合并，不能把过期基线直接覆盖过去。

### 7.1 KeePass

KDBX 文件视为有对象身份、历史和删除信息的数据库，不是普通 CSV。密钥文件、主密码和数据库加密参数需单独处理。

读取 → 验证 → 保留原文件备份 → 对象级合并 → 写入临时文件 → 用目标客户端／解析器验证 → 在版本未变化时提交。并发发生时重新读取合并，不能仅保留最新文件时间。

对未知插件字段、格式版本或密钥提供器无法保真时进入只读／导入模式，避免原地写坏用户文件。支持的客户端、算法和格式组合以测试记录为准。[格式与同步依据](08-references.md#s16)

### 7.2 1Password

迁移与持续连接分开：1PUX 导入不代表 CLI 连接完成；手机凭据交换不代表手机后台持续读写。

CLI 只处理明确授权的来源库。读取基线、字段变化与来源更新后再提交；保留来源条目映射，验证附件和隐藏字段没有被丢弃。会话过期时等待重新授权，不重复发起无限授权请求。[授权依据](08-references.md#s15)

## 8. Safari 与通用文件交换

### 8.1 输入

接受经验证的 HTML 收藏夹文件及官方导出包中相关条目，保留层级、标题、URL 和顺序。只导入用户选择的数据；导出包中额外出现密码文件，不默认一起导入。

解析不执行 HTML、脚本或附件。限制文件大小、嵌套深度、压缩展开比例和路径，拒绝目录穿越和不安全外链加载。将可疑 URL 显示为文本，不能在预览阶段自动打开。

### 8.2 输出

生成 Safari 可接受的文件并检查本产品能重新解析；还必须用 Mac 与 iPhone Safari 实际导入验证。本产品自测回读不能代替目标应用测试。

文件生成成功只能显示“导出成功”。没有目标应用回执时，不声明 Safari 已导入、已去重或已全量一致。

### 8.3 重复与删除

再次导入相同文件在本产品侧应幂等。Safari 自身再次导入的合并方式须实测，不能保证无重复。文件缺少某条目不自动构成删除请求；普通导入不执行“缺失即删”。

用户若需要替换 Safari 原有数据，必须提供清晰手动步骤和备份，属于额外的显式操作，不把覆盖现有数据作为默认导入方式。

## 9. 保险库导入导出

流程为：解析到暂存区 → 验证格式和完整性 → 生成字段与附件报告 → 预览 → 事务提交 → 回读核对。失败前后都能回到原库。

报告至少包含总数、新增、合并、跳过、重复候选、失败和未支持字段；不得记录密码明文。导入原始扩展字段加密保存；未知格式不能只保留一个成功计数。

通用 CSV 仅用于可表达的字段，不能作为完整保险库备份。完整导出必须覆盖附件、历史或明确说明是否包含历史、未知字段以及可导出的凭据类型，并能在干净安装恢复。Passkey 的可迁移性以原系统与交换协议验证为准。

文件导出可能是明文，界面在导出前说明性质和保存位置；优先加密备份，不默认上传明文到网盘。用户已有的源文件不擅自删除；本产品临时文件按明确生命周期清理，不承诺不可恢复地擦除 SSD 或外部备份。

## 10. 存储适配与提交

### 10.1 共同契约

只传输认证后的密文对象，采用唯一操作身份和可重试提交；只有验证过的完整对象才进入可见状态。并发算法不得依赖所有服务端都提供文件锁或原子目录重命名。

建议评估不可变操作／内容对象与本地事务索引，避免多设备覆盖同一个大文件；是否分段、快照与压缩由手机性能和网盘文件数量测试决定。公共线格式冻结前必须验证乱序、缺对象与中断。

### 10.2 WebDAV

探测实际服务器的目录列举、条件创建、强 ETag／条件更新及权限行为。共享可变索引需要并发保护；若无法可靠实现，则选择验证过的不可变对象方案或拒绝启用自动写回，不能退化成无条件覆盖。

分清认证失败、无权限、路径不存在、配额已满、证书错误与网络超时。自动重试有退避与上限，不跳过 TLS 验证。[WebDAV 依据](08-references.md#s24)

### 10.3 本地／网盘目录

本地写入成功仅代表当前设备持久化。另一端可能只收到部分对象、冲突副本或旧索引，应等待完整性验证再合并。重启、目录撤权、文件被移走和文件尚未下载都不能被解释成空库。

iPhone 通过文件协调读写授权目录；缓存目录访问授权并处理失效，不扫描未授权目录。[目录依据](08-references.md#s23)

### 10.4 存储迁移

建议在明确迁移窗口暂停远端提交并排队本地编辑，复制密文和必要元数据，校验完成后切换主要位置。更新存储代次、通知设备，旧位置作为冻结快照保留。长期离线设备重连必须先检查代次，不能重新把旧库写成主库。

文件提供器无法强制锁住所有离线写入者时，必须给出可执行的设备重新连接步骤并保留旧位置变更以供核对，不能宣称切换后旧端写入会自动消失。

## 11. 状态与可观测性

用户界面使用可理解的状态：已保存到本机、待联网、待解锁、需来源授权、已上传、等待另一设备、部分内容未同步、手动导入导出。

内部记录操作计数、错误类型、协议版本、脱敏设备标识与时间。不得记录主密码、恢复密钥、验证码种子、完整 URL、用户名、Cookie、会话令牌、命令参数中的秘密或明文附件路径。

每次失败保留足够诊断信息和安全重试入口；诊断报告在用户预览后导出。详细验收见[测试与验收](06-test-and-acceptance.md)。
