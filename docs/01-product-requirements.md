## 1. 产品定位

面向公众的个人收藏夹与保险库工具，解决不同浏览器、设备和密码管理器之间的数据分散问题。用户既能保留现有工具逐步接入，也能把数据迁入我们的保险库统一管理。

软件、客户端、浏览器扩展和服务端全部开源，功能免费，不设置订阅或付费功能门槛。长期费用考虑自筹、赞助和捐赠；未承诺无限存储或已建立官方托管服务。

项目自有代码采用 [MIT 许可证](../LICENSE)，由项目负责人于 2026-11-18 确认。正式产品名称、最低系统版本和正式发布日期尚待确定。

## 3. 平台与来源

### 3.1 浏览器

- 目标浏览器：Chrome、Edge、Firefox、Safari，以及用户另一个项目的 Chromium 浏览器 Aegis。
- 桌面 Chrome、Edge、Firefox 以扩展方式实现收藏夹接入；Aegis 优先复用 Chromium 扩展，再实际验证差异。
- Safari 收藏夹采用文件导入、导出。Safari 网页使用自有保险库填充仍在目标范围。
- 移动浏览器逐平台验证，不能把桌面扩展支持直接套用到手机。
- 不要求用户必须安装 Aegis 才能使用本产品。本次文档不授权原生修改 Aegis。

### 3.2 密码来源

Apple「密码」、Google 密码管理工具、1Password、KeePass／KDBX，以及 Chrome、Edge、Firefox、Aegis 的现有浏览器密码，均纳入接入目标。

“Windows／Mac／iOS／Android 的密码”当前解释为这些设备中的网站和 App 登录凭据，不包含开机密码、Windows Hello 私钥或任意系统秘密。此范围解释不是已经获得读取这些设备数据的授权。

KeePass 兼容面向 KDBX 格式及 KeePass、KeePassXC、KeePassDX 等客户端使用场景；每个格式版本、密钥组合和客户端的往返兼容性均须验证，不宣称所有插件数据自动兼容。

接入模式为：持续双向、持续单向、用户主动迁移、实验性、未支持。一个来源可以对不同字段提供不同模式。

## 4. 关键使用流程

### 4.1 首次使用

1. 选择收藏夹、保险库或两者。
2. 选择自备存储；公开官方云暂不显示为可用服务。
3. 创建加密数据空间；保险库引导设置主密码、保存恢复材料并验证能够恢复。
4. 连接浏览器或导入现有数据，先看变更预览和兼容性报告。
5. 通过保险库解锁材料或已授权设备连接第二台设备。
6. 执行一次新增、修改、离线补传和恢复演练，展示真实同步状态。

不得把注册官方账号放在 WebDAV／本地文件夹用户的必经流程中。

### 4.2 收藏夹首次合并

以参与连接的浏览器配置文件为范围，汇集完整收藏夹树。预览各来源的文件夹、顺序及重复项。用户确认合并后才批量写回，写回前建立可恢复快照。

全量同步不代表自动连接所有浏览器配置文件，也不代表覆盖浏览器受管理的只读收藏。受限目录要显示例外，不静默跳过后显示“全部成功”。

**建议默认值：** 同网址出现在不同文件夹时保留；相同来源的重复导入保持幂等；不同来源的同名目录先预览，不仅凭 URL 或名称自动删重。详细规则见[数据与同步规则](04-data-and-sync-spec.md)。

### 4.3 Safari 固定文件交换

Safari 导出 → 将文件放在已配置的位置 → PBsync 后台合并并同步至自己的数据空间。首次确认目录及书签导出范围。

PBsync 写出兼容文件后显示“待 Safari 导入”。Safari 内新增、修改、移动、排序和删除完成回读后，才计入双向同步验收。

导入文件只证明当次内容，不提供可靠的删除日志或完整版本时间。Safari 中后续修改不会被自动监听；重复导入、排序、移动和删除传播单独验证。

### 4.4 连接外部密码库

选择来源 → 授权 → 选择来源保险库及目标保险库 → 查看支持的数据类型、方向和更新时间 → 首次预览 → 开启连接。

默认不会把某来源数据再写入所有已连接来源。多个外部库若指向同一目标库，应显示传播关系，明确用户已授权的连接范围。连接失效时展示“需授权／待同步／部分成功”，本地修改继续保留。

### 4.5 迁入后统一使用

导入前备份 → 导入报告 → 核对字段与附件 → 实际填充抽样 → 第二台设备读取 → 新设备恢复演练 → 用户决定是否停止旧库的连接。

迁移不会自动删除来源数据或停用来源账号。导入条目数一致不等于完整迁移；Passkey、附件和自定义字段必须分别核对。

### 4.6 保存与填充

保存和填充是两组独立设置。检测到表单输入不等于网站已接受新密码；检测不可靠时回到确认保存。自动保存须明确目标保险库，不把一次错误登录自动覆盖成现有有效密码。

填充前检查网站／App 身份和目标字段。用户主动选择填充是默认行为；自动填入仅针对用户已允许的网站，库未解锁、目标不明确或多账号不明确时不得猜测。填写后由用户提交登录。

系统凭据提供器的功能与平台限制优先于产品开关：某 App 无法检测保存时就提供手动入口，不能声称“所有 App 自动保存”。

## 5. 信息结构与状态

| 页面 | 核心内容 |
| --- | --- |
| 收藏夹 | 文件夹树、搜索、排序、来源、Safari 文件导入导出 |
| 保险库 | 库选择、分类、条目、附件、历史版本、回收站 |
| 同步与连接 | 当前主要存储、来源库映射、设备、最近成功同步、待处理数量 |
| 恢复与备份 | 恢复材料检查、备份列表、恢复预览、存储迁移 |
| 设置 | 保存／填充偏好、解锁策略、实验性连接、隐私设置 |

同步状态至少区分：仅本地保存、等待网络、等待解锁、需要外部授权、上传中、等待文件提供器、部分失败、已同步到存储、已被其他设备应用、手动交换。

不得把“文件写入本机目录”显示为“其他设备已收到”。

## 6. 补充设计建议

以下不是新增的用户已确认功能，属于执行现有需求所需的建议；开发前通过 M0 评审或测试定值。

- 收藏夹也采用传输前加密，与保险库独立持有密钥，避免解锁收藏夹同时解锁密码。
- 删除默认软删除并保留历史；保留期限、容量与清理规则在性能测试后确定。
- 支持离线读取已同步数据及新增修改；后台调度不承诺每隔固定秒数执行。
- 生物识别作为本机便捷解锁候选，不替代独立恢复材料。
- 附件按需下载，限制在配置与界面中可见；不做无限容量承诺。
- 诊断日志脱敏，默认不上传凭据、URL、用户名、附件或保险库内容；崩溃上传策略另行确定。
- 初版优先中文界面，国际化资源结构可预留；多语言数量尚未确定，不作为已确认首版承诺。

## 7. 范围边界与验收

内部原型允许使用有限测试条目验证核心流程，不代表公开试用完成。首轮公开试用仍需覆盖 Mac＋iPhone、两种自备存储、完整保险库、自有同步与导入导出、填充和恢复；平台受限接入按实际能力发布说明。

Passkey、自定义字段或外部双向连接若无法完成，需要写清阻塞及范围变更；不能通过把功能藏起来，将用户的完整目标默认为取消。Windows／Android 属后续平台阶段，桌面 Firefox 在首轮 Mac 浏览器验证中保留。

暂不纳入：家庭／团队共享、管理员后台、订阅计费、公开官方云运营、自动改网站密码、绕过平台权限、系统开机凭据同步。

完整验收用例见[测试与验收](06-test-and-acceptance.md)；开发顺序见[开发计划](05-development-plan.md)。
