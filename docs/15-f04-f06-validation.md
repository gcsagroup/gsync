## F04 自动同步

每个已解锁空间按自己的已保存配置同步。新增、编辑、删除、恢复、导入及扩展写入都会安排同步。同一空间合并短时间内的请求，一次只执行一轮。运行中又有变化时会继续核对。解锁与回前台会触发补传，App 可运行期间约每 30 秒检查对端更新。自动同步刷新数据时保留原有空闲锁定计时。

遇到暂时性连接失败，从 2 秒起退避重试，间隔上限 60 秒。待传修改已经保存在加密历史里，进程退出后可再次同步。错误密码、授权过期和空间身份冲突会在状态栏给出提示。用户仍可手动发起同步。

实际操作分两条路径进行。

1. 在 Mac 选择专用文件夹并保存位置，App 自动建立密文空间。浏览器保存新账号并更新一次后，第二实例直接从目录解密出 1 个登录项、2 个历史版本。[文件夹读回](../build/f04-f06/folder-peer.json)
2. 在最终 Mac 构建配置回环 WebDAV，让服务返回 503，新增“构建24离线恢复验收”。界面显示已保存并按间隔重试。完全退出进程，再用同一路径、同一构建、同一配置启动。解锁时仍能看到该收藏和重试状态。恢复服务后，新实例从服务器解密读到了该收藏，共 70 个条目、156 个版本。对端再上传“构建24自动回读”，Mac 自动显示新增收藏及已合并 1 个版本。全程使用自动同步。[构建 24 重启与反向读回](../build/f04-f06/build24-restart.json)

复测中修正了前台轮询可能沿用旧界面状态的问题。另一次验收选错测试空间时，客户端拒绝了远端空间身份不匹配的写入，随后在正确的收藏空间完成上述流程。Mac 进程与命令行实例承担双端角色，真实 NAS、跨物理设备和 iOS 后台调度仍需各自验收。

Chrome 和 Edge 加载项目生成的扩展目录。Firefox 和 Aegis 使用扩展自己的验收页驱动操作。测试副本附加启动验收页的钩子和专用回执宿主，运行的收藏、通信和配对代码与产品包一致，已逐文件核对。Firefox 启动时将应用数据和缓存一起指向临时目录，避开本机 macOS 27 对旧版 Firefox 默认数据目录的访问限制。[Mozilla 的问题记录](https://bugzilla.mozilla.org/show_bug.cgi?id=2078511)

焦点测试曾复现 App 批准后网页仍未取得焦点。最终实现先签发 15 秒内有效的一次性许可。扩展最多等待 8 秒，核对原标签、同一文档、完整地址和网页焦点后再领取凭据。App 再次核对解锁会话及条目版本。实测两次手动批准后，网页均回读到指定账号和更新后的密码，页面仍停在登录表单。许可重复使用或锁定后再使用均被拒绝。[首次填充](../build/f04-f06/chrome-real-fbk6g858/records.jsonl) · [第二次填充与默认保存确认](../build/f04-f06/chrome-real-j5osnrkf/records.jsonl)

本轮验证了四种浏览器的双向收藏、排序和重复同步。浏览器自带云同步同时在线、完整 F01／F02 样本、受管理的只读目录、商店安装和其他浏览器的网页凭据流程仍有独立验收条件。

## F06 默认确认与可选自动保存

用户在 Mac 的“同步与连接”选择授权保险库，为网站填写一个登录成功后才会出现的固定 HTTPS 地址，再生成配对密钥。在扩展设置读取规则，核对成功页后授权启用。未配置成功页时可从扩展读取表单并确认保存。

候选按标签页暂存，最长有效 2 分钟。自动写入要求同一标签页的首次顶层表单导航进入指定成功页，返回 2xx，页面已离开密码表单。手动输入地址、普通链接跳转、回退和超时均无法触发自动写入。App 会核对库身份、解锁会话、网站来源和提交前的账号版本，并在同一写锁内完成更新。已有多个候选账号、版本冲突或模糊页面需要用户确认或重读。此模式依赖用户所选成功页能可靠区分登录结果，单页应用的自定义成功状态另需适配。

在本机 HTTPS 登录站点实际提交了成功和失败的表单。Chrome 用例使用独立配置，为测试扩展预授予 localhost 访问权限，并仅在该测试进程固定所用测试证书。选库、规则读取、启用、关闭、提交、原生确认和密文回读使用产品代码。本轮没有记录浏览器首次请求可选站点权限弹窗的人工点击。

| 操作 | 实际结果 |
| --- | --- |
| 默认模式提交表单 | 保险库数量保持原值 |
| 主动读取表单并选择确认保存 | Mac 显示目标网站和账号，批准后保存，重复保存相同值没有新增版本 |
| 失败登录 | 保留原账号和有效密码 |
| 指定成功页上的新账号及密码更新 | 新增后独立解密回读正确，再次提交后读回新密码 |
| 同站另一个用户名 | 回到确认流程，保留原有账号及数量 |
| 在扩展恢复逐次确认 | 后续成功登录也需要明确确认才会改库 |
