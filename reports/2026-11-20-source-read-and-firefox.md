# KDBX 后台读取恢复与 Firefox 常驻准备

2026-11-20，北京时间。Mac 固定 App 路径 `build/GCSA-PBsync.app`，最终实操构建 Ver 5.1 (173)，扩展打包版本 2.1.6。本轮完成 KDBX 读取恢复、回收站过滤及实际候选校验；Firefox 只完成待签名包准备，完整密码双向同步仍未完成。

## 两项修复

1. 来源文件暂时缺失会被当作授权失败，连接被永久停用。现在保持已启用的连接和本地内容，显示自动重试；文件恢复后由原 30 秒检查继续读取。钥匙串暂时忙也不永久关闭连接。授权失败、格式损坏和库身份改变仍暂停，不循环请求授权。
2. KDBX 回收站密码及回收站子目录会被作为活动密码导入。现在读取时排除它们及历史条目，不影响原 KDBX 中的内容。对于此前已导入、后来在来源中缺少的条目，仍只报告缺失，不自动删除 App 副本。

两项均先建立失败回归，再修复通过。读取仍使用已授权来源及库身份检查；没有开启原地写回或扩大密码库权限。

## Mac 实际操作

所有密码、账号、网址、附件和库均为本轮合成数据，未连接日常密码库，也没有安装 KeePassXC 或 1Password。来源修改由真实 KDBX 库工具完成，App 通过随包连接器读取；这不能代替 KeePassXC 客户端的完整互操作验收。

| 操作 | 观察结果 |
| --- | --- |
| Mac (171) 首次选择 KDBX，预览并连接 | 预览 2 项，确认后出现在密码库，来源标为 KeePass |
| 修改来源标题、密码，并新增一项 | 未点击重新读取，App 自动变为 3 项并显示更新后的标题 |
| 暂时移走来源文件 | 提示“来源暂不可用 · 本地密码已保留，恢复后自动重试”，现有条目保留 |
| 恢复原路径并再次修改标题 | 未重新连接，App 自动收到恢复后的标题，状态回到正常读取 |
| Mac (173) 的干净连接读取 4 项活动记录、2 项回收站记录 | 仅导入 4 项，包括回收站子目录中的记录均未出现 |
| 查看更新后的合成密码、备注及附件 | 界面目视正确；持久数据导出后逐字节核对密码一致，临时明文 CSV 随即删除 |
| 在 App 修改标题并生成写回候选 | 显示待写回 1 项；候选独立重开后，标题、密码、未知字段及附件正确；该阶段原 KDBX SHA-256 不变 |
| 最终构建锁定后在来源新增第五项，观察超过 30 秒 | App 持久数据仍为 4 项，未读取来源新增内容 |
| 退出并重启同一 Mac (173)，再解锁 | 初始仍锁定；解锁后自动变为 5 项，本地候选标题修改保留；不需重新连接或重新输入 KDBX 密码，回收站条目未导入 |

临时签名从 (171) 升级到 (173) 后，旧测试连接的无交互钥匙串读取显示需要恢复授权，因此没有把“构建升级后直接恢复”记为通过。最终同一构建的重启验收使用干净合成连接；它证明同一构建的配置持久化，不证明升级授权已经解决。

独立验收结束后已锁定测试库并切回日常收藏夹，原主密码从原有钥匙串项目取回用于本机进程输入，没有重置或显示密码，临时输入文件已删除。日常书签只读回查为 332 条，完整目录、标题、网址和顺序与上轮回读一致。更新后的日常浏览器配对已发起原有钥匙串恢复，最终系统确认结果另行核对；未生成新配对密钥。

## Firefox 签名准备

- 当前两种扩展均为 2.1.6，最低 Firefox 版本改为 142，消除数据收集声明的版本兼容警告。
- Mozilla `web-ext` 10.8.0 检查两种 Firefox 包均为 0 错误、0 警告；归档含 MIT 许可，SHA-256、版本、权限和未签名状态由实际产物回读。
- 本机 Node 24.14.0 运行检查器时发生原生解析器崩溃；改用经官网 SHA-256 核对的 Node 22.23.5 后通过，未把崩溃算作检查结果。
- `build/extensions/pbsync-firefox-bookmarks.zip` 为可供审核的待签名包，未上传 AMO、未取得签名 XPI，也未替换日常临时扩展。完整流程见 [Firefox 签名准备](../distribution/FIREFOX.md)。正式版常驻安装仍需 Mozilla 签名及退出重启后的实际验收。[Mozilla 说明](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/)

## 剩余目标

- KDBX 反向仍只生成候选，不会自动替换原库；来源缺项不会自动删除 App 条目。
- 浏览器内置密码后台双向接入未实现；1Password 本机没有客户端、CLI 或已授权测试账号，本轮没有在线验收。
- Firefox 常驻仍待 AMO 账号、签名和签名包重启测试；日常临时扩展退出浏览器后仍会失效。
- 来源读取要求 App 运行且目标保险库已解锁，锁屏、手动锁定和退出时暂停；临时签名升级后旧钥匙串授权仍可能需要本人系统确认。
