# Mac 指纹解锁与 App 重启回读

2026-11-19，北京时间。Ver 5.1 (160)，本机 arm64 Mac、固定 App 路径、原有隔离资料和合成密码；系统指纹由本人完成。收藏夹和密码库均通过首次启用、锁定后指纹解锁，以及 App 重启后仅用指纹解锁与内容回读。

## 实现变化

- Mac 改用 CryptoKit 直接创建 Secure Enclave 保护的 P-256 密钥，以 `.privateKeyUsage` 和 `.biometryCurrentSet` 约束私钥运算；硬件私钥只导出硬件封装数据。
- 通过 ECDH、HKDF-SHA256 和 AES-256-GCM 保护 32 字节本机解锁密钥。文件仅保存封装数据、临时公钥、随机盐和密文，认证上下文绑定格式版本及当前资料文件路径，其他空间不能直接复用。
- 保留主密码、独立认证上下文、取消与锁定使旧操作失效的现有流程。保存前先验证硬件解封装，认证失败不覆盖已有记录；Mac 不再访问数据保护钥匙串，iOS 的钥匙串实现保持原样。
- `device-unlock/` 目录为 0700、文件为 0600，并排除系统备份。读取拒绝符号链接、非当前用户文件、对其他用户开放的权限、超限数据、未知版本与错误空间绑定；关闭功能只删除当前空间的本机记录。

## 实际验收

| 操作 | 观察结果 |
| --- | --- |
| 收藏夹用主密码首次启用 Touch ID | 本人触碰指纹后保存成功，没有签名权限错误；锁定后出现 Touch ID 入口 |
| 收藏夹锁定后仅点击 Touch ID 解锁 | 主密码框保持空白，指纹成功后显示原有合成书签及网址 |
| 密码库首次启用、锁定后指纹解锁 | 生成第二份独立记录；指纹成功后显示原有合成密码条目 |
| 退出 App，再以相同 App 和资料路径启动 | 确认旧进程结束；进程由 19606 变为 21608，初始两库均锁定，Touch ID 入口保留 |
| 重启后的收藏夹指纹解锁 | 未输入主密码，指纹成功后原有合成书签标题、网址一致 |
| 重启后的密码库指纹解锁和回读 | 收藏夹解锁不会打开密码库；随后仅用指纹打开密码库，条目标题、用户名和显示的合成密码均一致 |
| 结束检查 | 两个空间均锁定 |

重启后的首次观察检测到用户手动切页，因此重新锁定两库，再由 CUA 逐一发起指纹解锁并核对内容，以上以这组受控操作为验收依据。此轮不包含 macOS 系统重启。

成品回读为 `Signature=adhoc`、`TeamIdentifier=not set`，没有内嵌描述文件；CDHash 为 `2f73085a42601737b453fdb6aad7205e781eb254`。这次验证没有使用开发者账号或项目开发描述文件。两份本机加密记录的权限均为 0600。

## 使用边界

此方案需要可用的 Secure Enclave 和已登记的 Touch ID；新设备或记录不可用时使用主密码，指纹集合变化后需重新启用。没有数据保护钥匙串按应用签名隔离的那一层保障，本机文件权限不能阻止同一用户下已被攻陷的进程；仍由硬件访问控制要求指纹完成私钥运算。

尚未验证实际变更指纹集合、其他 Mac 硬件及系统版本、macOS 系统重启，以及本轮新构建的错误指纹与取消分支。系统凭据提供器、共享容器与正式发布的签名要求另行验收，本轮仅完成 Mac 本机解锁与 App 重启回读。
