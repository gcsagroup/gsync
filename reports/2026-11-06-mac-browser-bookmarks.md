# Mac 浏览器收藏夹同步实测

2026-11-06，在本机 Apple Silicon、macOS 27.0.1 上运行 PBsync Mac 4.0 (70) 和桌面扩展 2.0.2。四个独立浏览器配置共用一个合成收藏夹，只授权书签。Chrome 和 Edge 通过调试管道操作真实扩展，Firefox 和 Aegis 在测试扩展副本内附加验收页，产品同步脚本与打包源码一致。测试端使用本地开发通信宿主。

| 浏览器 | 实测版本 | 跨浏览器回读 |
| --- | --- | --- |
| Google Chrome | 156.0.8078.81 | 首次写入后保持在线，最后自动收到 Aegis 的新书签 |
| Microsoft Edge | 154.0.4258.37 | 收到 Chrome 改名后的书签，主动删除对照项后库内增加一条删除记录 |
| Firefox | 154.0.1 | 收到 Edge 改名后的书签 |
| GCSA Aegis Test | 155.0.8059.40 | 收到 Firefox 改名后的书签 |

每轮在浏览器原生收藏树创建文件夹和两个网址，预览后首次合并。随后改名并交换顺序，通过独立解密确认事件已写入 PBsync。再通过 CLI 向同一收藏库导入一个网址，调用扩展同步，在原生收藏树中查到唯一一条。连续同步两次，版本数稳定。最后用浏览器保存的 Bookmarks 或 places.sqlite 回读文件夹名、两个网址及顺序。Chrome 在 Aegis 完成后约 37 秒自动收到末端改动。[逐端回执](../build/bookmark-mac-final-cshwx6cf/summary.json)

**异常退出时的误删已修复。** 原扩展 2.0.0 在 Chrome 收到新数据、原生书签尚未落盘时被测试程序终止。重开后，旧目录树比扩展基线少 19 个节点，删除数从 0 升到 19。第一次修正保住了书签，但导出比对发现旧目录顺序仍会回传。2.0.2 只上传浏览器报告过的删除，遇到来源不明的缺项时，用收藏库补回缺项和已同步内容，同时保留本地快照与新建条目。[原始故障记录](../build/bookmark-mac-z1NQTl/crash.json)

最终按相同顺序终止 Chrome，再用同一配置启动。重开时查不到 Aegis 样本，扩展自动补回，正常关闭后从磁盘读到四个浏览器的测试文件夹。重开前后均为 **67 个活跃节点、2 个已删节点**。全库导出的 **48 个网址**连同标题、目录及排列顺序逐字节一致。导出文件 SHA-256 为 `f29c23604f1616b4ba9e946344a993f91bb953e4a99f36ed9313d5c14ab3d4cf`。[重开前后回读](../build/bookmark-mac-final-cshwx6cf/restart-readback.json)

统一回归 70 项通过，其中扩展 8 项。此次补测限本机同一 PBsync 空间，使用开发扩展和测试配置；浏览器厂商云同步同时运行、跨设备和商店分发留待独立验收。Safari 当前采用 HTML／ZIP 文件迁移。[统一测试](../build/validation-20261106-204240-931855/summary.json) · [扩展包校验](../build/bookmark-mac-final-cshwx6cf/extension-packages.json)
