# Edge 启动修复与 Safari 导入实测

2026-11-11。本轮未修改或重新构建 PBsync，仍为 Mac Ver 4.3 (91)、扩展 2.1.3。

## 结论

- Edge 已恢复正常打开，但后台同步仍未恢复。旧进程持续占用数据库，需在保存其他工作后重启 Mac，再验收扩展和同步。
- Safari 的浏览器内导入已由电脑工具实际完成，导入 2 条测试网址、3 个目录。不能将本轮界面操作称为 PBsync 已实现无人值守自动导入。
- Safari 测试目录已清除。原有 355 个节点（332 条网址、23 个界面目录）与本轮操作前完全一致；Edge 当前完整导出与原基线一致，332 条网址及目录顺序保留。

## Edge

已安装的官方 Edge 157.0.4341.42 中，14 个 Mach-O 程序文件缺少执行权限。仅恢复这些文件的执行位，原权限和 SHA256 保存在 `edge-executable-modes-before.json`。逐文件复核内容摘要不变，`codesign --verify --deep --strict` 通过。之后实际打开新标签页、扩展页和收藏夹页，并完成官方 UI 导出。

旧 PID 96177 仍为 `UE` 状态，已持续四天；两个旧渲染进程也处于相同状态。旧主进程仍持有日常配置中 Service Worker 与 PBsync 扩展数据库的锁。新实例显示 PBsync 2.1.3，但错误为 `Service worker registration failed. Status code: 2`。结合存活锁证据，不能通过删除锁文件或继续启动实例解决。

本轮未删除锁文件、未重置或改写日常浏览器配置、未重启系统。原权限记录可用于逐文件恢复，但恢复为缺少执行位会重新导致无法启动。

后续验收：用户保存工作并重启 Mac → 确认旧进程和锁持有者已消失 → 启动单一日常 Edge → 验证扩展存储及后台启动 → 使用独立目录验证新增、修改、移动、删除传播 → 再核对全部原有书签。重启本身不等于同步修复成功。

## Safari

在操作前通过书签编辑页连续读取 21 页，保存 355 个节点的标题、网址、目录直属项数量和顺序。本轮测试输入只有唯一测试根，包含“来源”和“空目录”两个子目录，以及两条 `example.invalid` 网址。

先选 ZIP 后未看到导入结果；改选 HTML 后，Safari 显示“成功导入 5 个书签”。过程中系统日志出现过本机认证取消，稍后实际导入成功；未代填或绕过系统验证。因此不能承诺无需本机验证的全自动运行。导入成功后选择保留原测试文件，展开目录回读两个网址、中文及 `&` 字符和空目录，均正确。

只删除本轮唯一测试根，再连续读取 21 页。前后 355 个节点逐项完全一致，后测页间最少重叠 18 个节点，未遗留测试项。没有重复导入日常整库。

此次验证证明电脑工具可以完成浏览器内导入，不证明产品已具备后台持续同步。现有文件导入也不能直接承担修改、移动和删除同步；连续重导整库会造成重复风险。没有把这一流程接入自动循环。
