# 日常来源恢复与书签同步复验

2026-11-19，北京时间。Mac 固定 App 路径 `build/GCSA-PBsync.app`，实操构建 Ver 5.1 (166)，仅书签扩展 2.1.5。日常收藏夹恢复可用，Chrome 与 Firefox 的连接和自动传播通过本次实际操作；密码来源的持续双向同步仍未完成。

## 为什么之前没有看到日常数据

1. 指纹验收启动的是独立资料目录，界面中的 “Biometric QA” 和 “Mac Restart QA” 是合成测试内容。该目录不包含日常收藏夹，也没有自动继承日常浏览器授权。
2. 原日常收藏夹仍在，处于锁定状态；临时签名构建更换后，原浏览器配对还需要系统钥匙串确认。原主密码是此前验收生成并保存在本机登录钥匙串中的密码，本次从对应项目取回，未重置密码或新建替代库。
3. Firefox 以前临时加载的扩展已随浏览器退出消失。本次经用户明确同意，重新加载现有仅书签扩展并恢复本次会话。
4. “固定位置没有书签文件”属于文件交换来源状态，不能证明浏览器扩展已连接；旧的远端重试文案也没有清楚区分本机保存、钥匙串等待和访问同步位置失败。

## 修复范围

- 独立资料启动后显示“独立资料模式”，说明来源需要单独连接；侧栏改为“后台连接检查已启用”，避免把设置开关描述成来源已经同步。
- 本机模式显示“仅保存在本机 · 尚未设置设备间同步位置”，清除残留的远端重试状态；钥匙串读取等待、读取失败和远端访问失败分别提示。
- 成功预览也更新扩展请求时间。扩展弹窗显示最近成功或失败原因，成功后清除旧错误。
- 复现并修复书签并发覆盖：另一端修改标题和备注，本端仅调整顺序时，旧代码提交完整条目，会覆盖新标题并清空备注。新扩展带上次确认的字段，App 在同一事务内只应用实际变化的字段，保留其他内容。旧版缺少基线的变更请求被拒绝并提示升级；预览仍可用。同一字段的并发操作仍不能仅凭浏览器事件推断真实发生时间。
- 扩展更新到 2.1.5，沿用现有权限、身份和配对；没有扩大到密码库授权。

## 备份与恢复结果

操作前在私有本地目录备份日常 PBsync 资料、来源书签及扩展配置，逐文件核对原件、备份及 SHA-256。未读取或复制浏览器密码库。确认实际日常浏览器配置，排除包含 500 条合成书签的 Aegis 验收配置。

原共享收藏夹包含 332 个网址，与 Chrome、Edge、Aegis 日常配置中的有序网址及标题一致。恢复后使用原配对连接 Chrome；Firefox 经首次预览和保留合并恢复连接，没有轮换令牌或清空现有书签。

| 操作 | 实际观察 |
| --- | --- |
| App 新增一个临时测试书签 | Chrome 自动收到；Firefox 恢复会话时合并收到 |
| Chrome 修改测试标题 | App 自动回读；Firefox 随后台拉取收到同一标题 |
| Mac (166) 与扩展 2.1.5 受控复验 | 在 Chrome 再次修改临时标题，App 和 Firefox 自动收到，修改后未点击手动合并 |
| App 将该测试条目移至回收站 | Chrome 和 Firefox 自动删除该条，未清空回收站 |

| Firefox 自身导出 HTML 与操作前数据库快照比较 | 332 个网址、书签菜单及其他根下的完整用户目录、标题、URL 和顺序一致 |

初次反向改名过程中观察到旧标题回退，具体时序没有独立定论。随后用合成回归测试确定了“排序覆盖新标题及备注”的结构性缺陷，修复前失败、修复后通过；最终实际操作以上述 2.1.5 受控复验为准。

恢复过程中不删除旧空间、不覆盖原主密码、不清空浏览器书签。临时用于本机进程输入的密码文件在结束后删除，原钥匙串项目保留；备份与书签导出仅保留在私有本地 `build/` 目录，不提交 GitHub。历史中保留本次测试条目的可恢复删除记录。

## 仍未完成的目标

- Firefox 当前连接只在本次会话有效，尚未完成签名分发与重启后持续加载。
- Edge、Aegis 本次只做日常书签完整性核对，没有把文件一致算作它们的运行中自动同步复验。Safari 仍依赖文件交换与 Safari 端导入。
- 日常资料尚未设置设备间同步位置，本轮不证明 iOS、Android、Windows 或其他设备已收到这份数据。
- 日常资料目录没有已连接的密码保险库，本机未检测到 `op` 或 `keepassxc-cli`。浏览器内置密码库的后台双向接入未实现；KeePass 仍是读取与写回候选，1Password 仍需明确来源授权和写回验收。界面中的来源标签不表示已发现或同步真实密码。
- 本轮没有修改真实来源密码、移动旧保险库或绕过系统安全确认。生物识别解锁完成与外部密码数据同步完成是两项独立验收。
